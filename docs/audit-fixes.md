# ผลแก้ไขจากการตรวจระบบ — 14 ตุลาคม 2569

ใช้ Sol 6.1 แบ่งงานความปลอดภัยรูป, retention/recovery, Kiosk และประวัตินักเรียน โดยผู้ประสานงานตรวจรวมและทดสอบระบบทั้งหมด ยังคงการเข้าสู่ระบบนักเรียนด้วยรหัสประจำตัวและกติกา Coins เดิม

## สิ่งที่แก้แล้ว

- Sharp 0.35.5 และ source-map-js 1.2.2; ตรวจลายเซ็นรูปก่อน decode และอนุญาตเฉพาะ JPEG/PNG/WebP buffer loaders
- แยก `evidenceDetachedAt` จาก `evidenceDeletedAt`; งานลบ Drive ที่ล้มเหลวเก็บคิวและประวัติ retry จนลบครบทั้งสองรูป การตอบ client ไม่ส่งรหัสไฟล์ในคิวลบ
- การอนุมัติต้องมีหลักฐานหลักที่ยังไม่หมดอายุ รูปจุดทิ้งใบที่สองยังไม่บังคับ
- heartbeat ที่เน็ตหลุด/5xx ไม่ล้างฟอร์ม และปุ่มลองเชื่อมต่อไม่ส่งรายการแทนการต่ออายุ session; 401 ของ login ที่ PIN ผิดไม่ถูกตีความว่า session นักเรียนหมดอายุ
- logout, idle timeout, เปลี่ยนบัญชี และ response เก่าล้าง/ป้องกันข้อมูลข้ามบัญชีตามเดิม
- สถานะประวัติกรองจากทั้งบัญชี พร้อมจำนวนรวมและหน้าแยกจาก ledger/รางวัล มี RPC อ่านเฉพาะผลของนักเรียนคนเดียว และ fallback สำหรับ schema เดิมที่ตรวจ version รอบการอ่าน
- Audit มี actor ID/role ถาวร; error มี event ID โดยไม่ log PIN, cookie, token หรือรูป
- หน้าเจ้าหน้าที่เตือนผล backup/maintenance เก่าหรือคิวผิดพลาด พร้อมเครื่องมือตรวจสถานะแบบอ่านอย่างเดียว
- สำรองจะรายงานสำเร็จหลังตรวจ manifest/blobs และการเก็บตามอายุครบ มีผลความล้มเหลวแยกจากผลสำเร็จล่าสุด
- เครื่องมือซ้อมกู้คืนใช้ฐานข้อมูลชั่วคราวแยก ตรวจยอด/stock/ledger/รูป และทำลายพื้นที่นั้นหลังตรวจ; `--record-health` บันทึกได้เฉพาะผลตรวจที่ผ่าน ไม่คืนข้อมูลลง cloud

## ผลตรวจ

- `npm run test:all`: 59 tests, build และ browser flow ผ่าน รวมกรณีเน็ตหลุด/503, หมดเวลา, response ข้ามบัญชี, PIN ผิด และประวัติ 120 รายการที่กรอง/แบ่งหน้าได้ การตรวจฐานข้อมูลใช้ WASM ที่เตรียมจากไฟล์ local เพื่อหลีกเลี่ยงปัญหาเริ่มต้น PGlite บางครั้งบน Windows
- `npm audit --json`: 0 ช่องโหว่ ณ วันที่ตรวจ ไม่ใช่การรับรองว่าจะไม่มีช่องโหว่ใหม่ในอนาคต
- SQL RPC ทดสอบจริงผ่าน PGlite พร้อมตรวจว่า anon/authenticated เรียกไม่ได้ ข้อมูลและลำดับหน้าตรงกับ SQLite
- ทดสอบกู้ snapshot จริงวันที่ 14 ตุลาคมลง SQLite แยก กระทบยอดผ่าน พร้อมรูปหลักฐาน 3 รูป ผลนี้ไม่รวมการย้ายกลับ Supabase/Drive หรือ RTO ของเว็บจริง
- ตัวรัน unit tests เรียง test files เพื่อเลี่ยงการเริ่ม PGlite พร้อมกันที่ค้างบางครั้งบน Windows; การทดสอบ race ภายในชุดทดสอบยังทำงานพร้อมกันจริง

## ผลเดินระบบและขอบเขตที่ยังต้องตรวจ

1. ติดตั้ง index/RPC `wb_student_history` ลง Supabase จริงแล้ว ทดสอบอ่านข้อมูลจริงผ่าน และตรวจว่า anon/authenticated เรียกไม่ได้ service_role เรียกได้
2. เตรียม runtime/env/backups ถาวรที่ `%LOCALAPPDATA%/WasteBankOperations` จำกัด ACL ให้ผู้ใช้ปัจจุบันกับ SYSTEM สำรองก่อนเปลี่ยนฐานข้อมูลและซ้อมกู้ snapshot จริงลงพื้นที่แยกผ่าน
3. Task Scheduler ในเครื่องนี้เรียกงานไม่สำเร็จ แม้เรียกตรงได้ จึงปิดเฉพาะงานที่สร้างไว้และใช้ Startup ของบัญชีผู้ใช้แทน เปิด Node แบบซ่อนหน้าต่าง สำรองทุกวัน 08:00 Asia/Bangkok จับงานที่พลาดหลัง resume และลองใหม่หลังผิดพลาด 15 นาที ตรวจการทำงานจริงจาก PID/status และไฟล์สำรองที่อ่านกลับแล้ว ต้องล็อกอินและเปิดเครื่องไว้ ผลนี้ยังไม่ใช่การรับประกันว่าเครื่องจะออนไลน์ทุกวัน
4. เจ้าของระบบเลือกสำรองในเครื่องก่อน ยังไม่มีสำเนาแยกเครื่อง คีย์และสำเนาบนดิสก์เดียวกันยังสูญหายพร้อมกันได้เมื่อเครื่องเสีย
5. เพิ่มการซ้อม backup → SQLite → PostgreSQL แยกพร้อมรูปสองใบในชุดทดสอบ แต่ใช้ PGlite/Drive จำลอง ยังไม่ได้สลับ deployment หรือย้ายข้อมูลจริงกลับขึ้น cloud การทดสอบโฟลเดอร์ Drive จริงผ่าน และมี health ของ cron ที่ไม่มีคิวค้าง
6. ชุดนี้ปล่อยผ่าน GitHub main ตามคำสั่ง deploy ของผู้ใช้ ต้องตรวจสถานะ deployment และ asset ของเว็บจริงหลัง push ก่อนรายงานว่าสำเร็จ

คำเตือนหน้าเจ้าหน้าที่เป็นการแสดงในเว็บและ exit code ของเครื่องมือตรวจ ยังไม่ได้เชื่อมบริการส่งการแจ้งเตือนภายนอก
